四条设计原则

原则 01

两层动作，风险分级

布局改坐标，零风险、秒回滚；移动改文件系统，需逐条确认。

两者都做，但预览里用不同视觉标识分开呈现。

原则 02

LLM 只做判断，不做动作

Agent 输出分类方案 JSON，动作由确定性代码执行。

幻觉最多导致分类不准，不会导致文件丢失。

原则 03

收纳盒视觉优先

默认只框住图标，文件一个都不动。可选升级为物理收纳。

这个默认值决定第一印象：打开就能用，不怕。

收纳盒：两档形态

轻收纳盒（默认）

视觉容器 · 不移动任何文件
  • 半透明圆角底板，顶部标题栏显示名称与图标数
  • 可拖动、缩放、折叠（折叠后只留标题栏）
  • 双击标题栏改名，右键改色 / 解散
  • 图标坐标被约束在容器内，文件零改动

自由命名的收敛机制

自由命名最大的坑是每次跑出不同分类体系——这次「游戏」，下次「游戏娱乐」，再下次「Games」，桌面越整越碎。三层收敛：
  • 上下文注入　每次调 LLM 时把已有分组列表传入，要求优先复用，确有必要才新建
  • 相似度合并　新名与旧名做编辑距离 + 语义相似度比对，超阈值提示「是否并入『游戏』？」
  • 字典沉淀　所有用过的分组名持久化为本地资产，可手动重命名 / 合并 / 删除

Rust 技术栈

crates/shell-winWindows Shell COM 封装，唯一 unsafe 集中区核心
crates/core采集 / 分类 / 布局 / 执行，无 UI 依赖可复用
crates/storageSQLite 持久化（rusqlite + bundled）
crates/mcpMCP Server，stdio + http 双模式rmcp
crates/appTauri 2 桌面应用 + 托盘UI
成本要提前认账：COM 样板代码比 C# 多、PIDL 生命周期要手动 CoTaskMemFree、全屏透明浮层需 WS_EX_LAYERED + WS_EX_TRANSPARENT。缓解办法是全部收口到 shell-win 一个 crate，对外只暴露安全 Rust API。万一卡住，可把这一层换成 C# sidecar，其余保持 Rust。

路线图

M0 · 可行性验证 1–2 周

装 rustup + MSVC Build Tools，跑通图标坐标读写、.lnk 深解析、DPI 兼容。产出：能把图标摆成三列的控制台 Demo。

M1 · MVP 3 周

扫描 + 规则引擎 + 分区布局 + 预览浮层 + 轻收纳盒 + 撤销。只做布局，不动文件。

M2 · 移动与收纳 3 周

文件移动 + 逐条确认 UI、重收纳盒、完整快照体系、占用检测与敏感文件排除。

M3 · 智能 3–4 周

LLM 双模式、自由命名收敛、自然语言指令、修正学习。

M4 · 生态 3 周

MCP Server 发布、规则市场、工作/娱乐模式切换、增量守护。

5

6
desktop_undo　写入·可回滚　随时还原到任意快照
分类引擎的真实难点：当前桌面 35 个条目里，Sciland、Yaak、Zed、夸克 四个光看文件名无法判断归属——必须解析快捷方式目标路径、PE 版本信息和图标才能定类。这四个是最佳的引擎验收样本。
