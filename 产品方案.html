为什么"折叠"被删掉了

v0.2 写"折叠后把图标坐标堆在标题栏下方"。但堆叠不等于隐藏——图标仍然可见、可点、可框选，堆在一起还会导致点击命中错乱。

Shell 没有任何"隐藏单个桌面图标"的接口。所以轻盒的"折叠"只能是紧凑化（图标排得更密，全部可见），要真正收起必须用物理盒。UI 上不再出现"折叠"这个词。

窗口层级：三态互斥

常驻态

默认状态
  • 盒子边框窗口 SetParent 到 WorkerW
  • 位于壁纸之上、图标之下
  • 图标浮在盒子上，点击正常穿透
  • 标题栏区域预留空白，不被图标盖住

预览态

仅整理时出现
  • 全屏浮层，Topmost
  • WS_EX_NOACTIVATE 不抢焦点
  • 拖拽图标跨盒、调整分区
  • 确认后执行并关闭

编辑态

改配置时
  • 复用预览态窗口
  • 改名 / 改色 / 合并 / 解散
  • 转为物理收纳
  • 不与常驻态同时存在
关键取舍：布局持久，容器临时。应用退出后盒子边框消失，但图标坐标是 Shell 持久化的，会保留。用户看到"布局还在但框没了"是预期行为，不是故障。

承诺边界

能力承诺不承诺

授权链路

v0.2 的漏洞

confirm: true 由调用方 Agent 自己填写。它只能表达"Agent 想执行"，不能证明用户同意执行。涉及文件移动的授权不能来自工具参数。

v0.3 的机制

  • 主程序弹逐条列出源→目标的确认面板
  • 用户点「执行」后签发一次性凭证
  • 凭证绑定：plan_hash + 桌面指纹 + nonce + 60 秒过期
  • 方案改了 hash 就变，必须重新确认
  • 执行层校验路径白名单，拒绝 .. 穿越

分类：五层优先级链

优先级来源说明
1用户明确指定 / 锁定最高，模型永不覆盖
2用户手写规则
3用户已确认的学习规则三次同类修正 → 提出建议，用户确认后生效
4内置规则包
5模型建议仅在 1–4 都未命中时使用

置信度从哪来

不用模型自报的概率
  • 每个信号组合维护历史命中计数
  • 置信度 = 用户接受率的 Wilson 下界
  • 冷启动无数据 → 全部进"建议区"
  • 用户确认的过程本身在积累数据

M0 对照实验

验证 AI 是否真的降本
  • A 组：纯规则　B 组：规则 + LLM
  • 指标：修正项数 / 确认耗时 / 24h 后查找时间
  • 判定：B 的修正项比 A 低 30% 以上
  • 未达标 → 产品定位需重新评估

隐私：一个具体的实现缺口

GetImage 默认返回的是缩略图

官方文档原文："The default behavior is to load a thumbnail." 一个 报告.docx 的"图标"实际是文档内容的缩略图。如果经 desktop_get_icon 交给外部 Agent，文档内容就传出去了。

修正：所有提取强制 SIIGBF_ICONONLY (0x4)，加单元测试断言，禁止任何不带该 flag 的调用路径。

字段是否上传处理
完整路径永不仅本地用于规则匹配
文件名条件默认脱敏，开关打开才原文发送
快捷方式参数永不可能含令牌、账号、路径
URL 查询参数剥离只留 scheme + host + path
图标图像条件强制 ICONONLY，不含内容
公司名 / 签名主体是明文

分阶段验收

M0 · 技术与价值验证

10 项通过条件

可交互桌面区域原型 + 规则/LLM 对照实验 + 异常恢复报告。验证拖动延迟、双击打开、框选、Win+D、Explorer 重启、崩溃恢复、副屏负坐标。

任一项交互不通过 → 收纳盒方案重新设计，MVP 不启动。对照实验未达标 → 产品定位重估。

M1 · 首次可用版本

7 项通过条件

扫描、分类建议、预览、布局、撤销、基础增量提示。

新用户 5 分钟独立完成整理；手动调整必须保留；强杀进程不出现图标不可访问。

M2 · 受控文件归档

7 项通过条件

可信确认界面、冲突处理、逐项日志、中断恢复。

同名冲突不覆盖；10 项中 3 项失败时撤销只回滚 7 项；无凭证的写请求必须被拒绝。

M3 · 能力扩展

6 项通过条件

双模型体验、自然语言、MCP 发布、规则学习。

抓包审计无路径/缩略图/参数外传；本地模型失败不自动上云。
