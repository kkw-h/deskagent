产品方案 · v1.0 · 转向版

DeskAgent

给桌面整理器装上语义大脑。不重做桌面工具，只做它做不了的那一层——判断每个图标到底是什么。

为什么转向

理由 01

该做的有人做了

PecoFence 用 21 天 10 个版本做到了栅栏、折叠、标签页、多屏、动态壁纸取色。DeskBox 把原生质感做到极致。

重做这些是几十人月的重复劳动。

理由 02

我们缺的那层恰好没人做

PecoFence 的规则只认扩展名、类型、文件名、大小、时间。

它不知道 Yaak 是 API 调试工具、Sciland 是游戏。

理由 03

成本集中在最不该自研的部分

Shell COM、WorkerW、坐标操纵、watchdog、Direct2D 是苦力活，已有成熟实现。

而语义判断才是真有壁垒的部分。

产品边界

DeskAgent 做

语义与决策
  • 枚举桌面条目
  • 解析 .lnk 目标路径、PE 版本信息、数字签名
  • 语义分类判断
  • 把方案编译成 PecoFence 规则
  • 调 pecofence-cli 落地
  • 增量监听与归位

PecoFence 做

渲染与交互
  • 渲染栅栏、玻璃效果
  • 折叠、标签页
  • 图标提取、缩略图
  • 拖放、右键菜单、重命名
  • 多显示器布局
  • 崩溃恢复、watchdog

工作流

scan → classify → plan → 人工审阅 → compile → apply
紫色是我们，绿色是 PecoFence。PecoFence 未安装时仍可独立输出方案 JSON，不绑死。

技术核心：规则编译

分类结果必须拆成两半

PecoFence 的规则引擎是属性驱动的，不是语义驱动的。所以同一个分类结果，要拆成「能变成持久规则的部分」和「只能一次性移动的部分」。

分类依据例子能否变成持久规则
扩展名.pdf/.docx → 文档能　rule add --ext pdf,docx
类型所有安装包 → 归档能　rule add --type installers
文件名名字含 Chrome → 浏览器能　rule add --name-contains
语义Steam.lnk 目标是 \Steam\steam.exe → 游戏不能　规则表达不了
这就是本产品存在的全部理由：语义分类无法沉淀成 PecoFence 规则，新装的游戏不会被自动归类。所以增量守护必须由 DeskAgent 自己做——不能指望 PecoFence 的规则引擎。

落地方式

# 1. 先快照，保证可回滚
pecofence-cli snapshot save "deskagent-before-apply"

# 2. 可规则化的部分 → 持久规则
pecofence-cli rule add --name 文档 --ext pdf,docx --to 文档

# 3. 语义分类的部分 → 一次性移动，先 dry-run
pecofence-cli item move --glob "Steam.lnk" --from 桌面 --to 游戏 --dry-run

# 4. 确认无误再执行
pecofence-cli item move --glob "Steam.lnk" --from 桌面 --to 游戏

超时（退出码 4）不重试——先 fence list 读回状态再决定，因为请求可能已生效。

CLI 命令

命令作用
deskagent scan扫描桌面，输出条目清单
deskagent classify分类，输出方案
deskagent plan --out plan.json生成可审阅的方案文件
deskagent apply plan.json落地，调 pecofence-cli
deskagent watch增量守护
deskagent describe / skill自描述，供 AI agent 发现能力

选 CLI 不选 MCP：编码 agent 都有 Bash 工具，MCP 需额外配置。后续要 MCP 只需把命令映射成工具。

路线图

M0 · 分类准确率验证 1 周

scan + classify，只输出方案不落地。通过条件：35 个快捷方式中 ≥33 个拿到目标路径，规则分类准确率 ≥80%，Zed/Yaak/Sciland/夸克 四个难点样本全部正确。

M1 · 落地到 PecoFence 1 周

适配层 + apply。一条命令完成从扫描到布局，快照可回滚，重复执行幂等。

M2 · 规则编译与增量守护 2 周

规则编译器、watch 增量归位、学习规则沉淀。新图标 5 秒内给出归位建议。

M3 · LLM 与评测 2 周

双模型接入、对照实验、自描述。判定线：操作数比手写规则低 50% 以上。

总工期约 6 周，对比 v0.3 的 13–15 周，省下的全是渲染和 Shell 交互。
